# 完整路线图

## 总目标

把科研方向转换成有证据、可执行、可追溯、可评估、可迭代的 Research Search Package，并逐步接入后续论文获取和阅读工作流。

## 阶段总览

| 阶段 | 核心建设 | 完成定义 | 主要风险 |
|---|---|---|---|
| P0 | 研究范围、OpenAlex 元数据、候选术语证据、三类查询、日志和离线评测 | **代码完成；真实三策略检索、重放和证据链已通过** | 数据源覆盖、API 限制、术语语义漂移 |
| P1 | 多轮反馈优化、增量收益、遗漏分析、预算和停止规则 | **代码完成；真实2轮/6请求对照停在待人工审阅** | 自我确认偏差、把相关性误当真值 |
| P2 | PubMed/MeSH、Semantic Scholar、独立语义与引文通道、跨源去重 | **代码完成；Provider/融合/主流程接入测试通过；PubMed 已真实小预算联调成功，Semantic Scholar 同主题请求返回 HTTP 429 并保留失败审计** | 授权、字段不一致、重复和覆盖错觉 |
| P3 | 对接合法论文获取、Obsidian/阅读工作台、检索包增量更新 | **代码完成；真实P0包已导出14篇阅读卡片；不下载全文、不写Vault** | 付费资源、沙箱和元数据漂移 |
| P4 | 多领域基准、人工审阅、增量更新、可选前端/服务 | **代码完成；真实P0/P1账本已汇总；无真值、不宣称优势** | 过早平台化、指标游戏化 |

## P0：证据支撑的策略生成

### 交付

- 英文 Agent Skill 包。
- Python 确定性模块和 OpenAlex 客户端。
- JSON Schema 与固定样本。
- 竞品/官方资料索引。
- P0 使用示例与真实接口记录（成功或失败均可交付，但须如实标注）。
- 工程和探索性评测报告。

### 依赖

- Python 标准库优先；联网模块只在实际需要时引入。
- 不把 API Key 写进仓库；请求预算和超时可配置。

## 关键词知识网络：下一阶段专项

- [完整设计方案](keyword-knowledge-network-design.md)
- [分阶段路线图](keyword-knowledge-network-roadmap.md)

关键词网络不是高频词表，而是由原始观察、候选关系、人工审阅、显式采用和单变量实验组成的证据网络。候选词不能自动进入查询；P2 多源和 P4 test 结果只能在来源、channel、split 和人工标签边界清楚时反馈到网络。

## P1：闭环优化（代码与真实两轮对照已完成）

1. 记录每个查询版本、增量论文集合和候选词变更。
2. 对语义通道发现但词法通道未覆盖的论文做差异抽取。
3. 把新术语分成 equivalent、broader、narrower、related_task、alternative_method、application。
4. 以人工标记优先，模型判断作为待确认层。
5. 引入版本回退、预算上限、低收益停止和偏移报警。

验收：能回答“为什么添加、找回什么、带来多少新增相关论文、是否引入偏离”。

## P2：多数据库和独立发现通道（适配器代码完成，真实多源请求待授权）

- PubMed：MeSH + Title/Abstract，不能用 MeSH 替代自由词。
- Semantic Scholar：相似论文和元数据通道。
- 引文关系：仅在来源字段和实际接口能力确认后启用。
- 跨数据库：统一论文 ID、DOI、标题指纹和冲突审计。

验收：各通道执行次数、返回数量、去重数量、互补论文和失败原因可分开报告。

## P3：科研工作流集成（元数据交接与阅读导出已完成）

- 合法全文获取接口或人工交接。
- 论文库和阅读笔记的稳定 ID。
- Obsidian 等工作台的模板和检索包导入。
- 增量检索：仅记录新增、变化和失效证据。

验收：从检索术语到论文元数据、全文、笔记的来源链不丢失。

## P4：质量强化和可选产品化（评测框架与人工协议已完成，产品化仍待证据）

- 成熟、新兴、交叉、医学四类方向的独立测试集。
- 人工相关性标注规范和抽检协议。
- 运行成本、人工筛选时间和复现性统计。
- 只有当基线和策略差异有足够证据时，才考虑可视化界面或服务化。

## 所有阶段的计量纪律

- 理论搜索空间、历史运行、实际新增运行、保留配置、目标指标变化分开。
- 计划运行次数不写成已执行次数。
- 论文返回数量不写成相关论文数量。
- 关键词数量不作为成功指标。
- 没有独立标注集时，不报告伪精确的 recall/precision 结论。
